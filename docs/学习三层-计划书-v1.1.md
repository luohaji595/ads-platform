## 一、目标与非目标

### 目标
让系统具备三种今天没有的能力：

1. **知道自己有多不确定**（收缩层）——报告不再假装每个词都能判，而是分层说清哪层有证据。
2. **知道哪些搜索词是同一类**（语义层）——86 个搜索词归成 62 簇，把「72 个 cable 长尾」变成十几个可一次判断的簇。**不合并投放词，不增加建议数。**
3. **知道自己改动作的后果**（探索层）——用随机扰动换因果信息，把「降 bid 会掉单」从猜测变成系数。

### 非目标（明确不做）
- 不做深度学习 / 神经网络（7 单样本量下必然是过拟合）
- 不做跨账户迁移（B 阶段的事）
- 不做自动执行（写权限未开，且是花钱动作）
- 不用 LLM 算统计量（只判「簇→产品关系」这一件语义事）
- 不为了让报告好看而放宽目标 ACOS

## 二、前置结论：三件必须先说清的事

写排期之前，有三条实测结论会直接改变你对「做完能拿到什么」的预期。如果这三条不认，后面的工期估算都会失真。

### 2.1 收缩层救不了「降价建议」——我上一轮算错了

上一轮我说「收缩后 lat pulldown 后验 CVR 1.21%、目标 CPC $0.63、降价建议能出」。**那是拿全账户 CVR 1.37% 当先验算的。** scope 收窄到 JL-高位下拉后，账户基线就是 0.63%。

实测（`κ` MLE = 3000，撞网格上限）：

| 词 | 点击 | 单 | 裸 CVR | 后验 CVR | 目标 CPC | 对地板 $0.40 |
|---|---|---|---|---|---|---|
| lat pulldown | 281 | 2 | 0.71% | 0.64% | $0.34 | 仍低于 |
| lat pulldown machines | 210 | 1 | 0.48% | 0.62% | $0.33 | 仍低于 |
| lat pulldown machine | 102 | 1 | 0.98% | 0.64% | $0.34 | 仍低于 |
| cable machine | 111 | 0 | 0.00% | 0.61% | $0.32 | 仍低于 |

**所有词的目标 CPC 都在 $0.32–0.35，全部低于地板 $0.40。** 收缩把所有词都拉向 0.63%，因为 scope 内确实同质（κ=3000 就是这个意思）。

**所以收缩层的产出必须重新定义**：不是「救出建议」，是**「分层诚实度 + 组合层头条结论」**。它的价值在 2.3。

### 2.2 五个层级里只有一个有信号

卡方齐性检验（14 天，scope 内）：

| 层级 | 组数 | 点击 | 单 | z | 判定 |
|---|---|---|---|---|---|
| keyword_text | 6 | 723 | 5 | 0.82 | 不显著 |
| campaign | 10 | 1108 | 7 | 0.46 | 不显著 |
| placement | 4 | 1106 | 7 | 0.72 | 不显著 |
| match_type | 3 | 723 | 5 | −0.36 | 不显著 |
| **portfolio** | **11** | **4079** | **74** | **4.58** | **显著** |

**除了「组合之间」，没有任何更细层级存在统计可辨的差异。** 要在这个量级分辨 2 倍 CVR 差异，每组需约 16 单，而整个 scope 只有 7 单。

→ 「今天建议动 0 条」**不是 bug，是数据在说真话**。真正的问题是报告没有把这句话说出来，也没把组合层那条唯一显著的结论顶到头条。

### 2.3 组合层有显著差异，但**不能**变成可执行提案

```
本组合 JL-高位下拉   CVR 0.63%   ACOS 69.2%   $883.56
账户整体             CVR 1.81%   ——           $4,002.02
```

组合层 `z=4.58` 显著，说的是**不同品类之间转化率有差异**——这是应该的，臂力器和高位下拉本来就不是一个生意。这条结论的正确用法是**解释**，不是**派活**：

> 高位下拉的转化率约为账户的三分之一。这不是出价能修的问题，问题在产品/Listing/价格层。广告层只能止损，不能做增长。

**为什么不能做成「停投高位、同额挪去臂力器」的提案**（三条否决理由，都来自运营现状，不是统计）：

1. **臂力器现速约 161 天、美腰机约 45 天。** 周转这么慢的品，加投等于把现金压进库存，财务上不该加。
2. **跑步机、划船器已搁置。** 表里 CVR 好看的几个品，现在不是可加投状态。
3. **P0–P1 只做高位下拉 B0GLYS1HY 这一个垂直**（`policy_id=5 scope_p0_p1`）。跨组合挪预算超出当前 scope。

**所以这一节不做「同额挪走能得多少单」的外推表。** 那张表里 82.8 单是线性外推，我自己都写了「不能当承诺」，那它就不该出现在决策文档里当加粗数字——加粗就是暗示它是结论。

**正确产出**：报告头条写一句「本组合转化率是账户 1/3，广告层只能止损」，并把它归入「已知事实」而不是「今日待办」。今日待办仍然由词层/活动层的可判动作构成，没有就是没有。

### ⚠ 两处已被否决的做法，不要按旧版做

**否决一：不能把 `lat pulldown` 的两个活动合并成一个判定对象。**

我上一版把 P1.0 写成「修聚合键 bug」，说 `keyword_id` 该改成 `keyword_text`。**这是错的。** 两个活动虽然投同一个词，但：

```
L3-基础bid0.8        bid $1.00  225击 1单  CVR 0.444%  CPA $175.22
L3-基础bid0.4溢价1.4  bid $0.40   56击 1单  CVR 1.786%  CPA $87.06
```

- 出价差 2.5 倍，CVR 差 4 倍，**CPA $87.06 已经优于账户 CPA×0.7（$88.36），触发核心词保护，本来就不许降**。
- 合并后 R01 把动作落在「花费最高」的活动（$1.00 那个），对它出「停用或转诊断」。而 $0.40 那个被并进去一起承担——**它本来不该被动**。
- 这与 11/16 已批的「主词先观察、不停用」（`decision_id=80/81`，`reject_reason_code=observe_no_execute`）直接冲突。
- 也与「守 SP 位次」的运营意图相反。

**正确做法**：判定对象就是 `(keyword_text, campaign_id)`，保持现状不动。P1.0 不再改 `facts.py:513` 的聚合键。

**否决二：不能把 `lat pulldown` 和 `lat pulldown machines` 并成一个语义簇。**

我上一版说这是「单复数差异」。**这是错的，有铁证**：

```
投放词 lat pulldown          跑出的搜索词：lat pulldown(279击) / lat pulldowns(2击)
投放词 lat pulldown machines 跑出的搜索词：lat pulldown machines(186) / lat pulldown machine(5)
                                          / latpulldown machine(1) / lat pull down machine(1)
交集 = 空集    Jaccard = 0.00    重叠率 0%
```

两条流量**完全不交叉**，是两个独立需求。而且这两条也已经在 11/16 分开批了「先观察」（`decision_id=80/81`）。

**根因在我的算法**：我的 STOP 表里有 `machine`/`machines`，把单复数差异自己抹平了——`tok('lat pulldown')` 和 `tok('lat pulldown machines')` 都变成 `{lat, pulldown}`，Jaccard=1.00，必并。即使把 machine 从 STOP 里去掉，Jaccard 仍有 0.67 ≥ 0.60，还是会并。

**结论：token 相似度这个闸门本身就是错的，不是阈值问题。** 投放词的合并必须改用「搜索词流量是否重叠」做闸门（实测：scope 内任意两个投放词的搜索词 Jaccard 都是 0.00，因为它们各自精准吃自己的流量）。既然全都重叠为 0，**那就一个都不该合并**。

**所以 P1.2 的范围收窄为：只做否词侧的长尾聚簇（帮人做相关性判断），不做投放词的合并。** 这样它就不再承担「让建议区活过来」的任务——那个任务本来就不该存在。

### 关键设计：先测 CPC，不测 CVR
7 单的窗口测「降 bid 会不会掉单」需要几百单，做不到。但测「降 bid 会不会掉曝光、CPC 会不会降」只需要点击——1108 击足够。

**不要跳过 CPC 直接测 CVR**，那是拿 7 单估三个参数，必然过拟合。

## 八、依赖与顺序

```
P1.0 报告说清没证据（1d）
   ├──→ P1.1 收缩层（2d）              ← 让报告说得准
   └──→ P1.2 语义层（2d，仅否词侧）     ← 省人的判断时间
              └──→ P1.3 探索层（2d，等执行层）
```

**P1.0 必须最先做**，因为它是「报告不再靠空白表达无证据」的基础，P1.1/P1.2 产出的东西都要挂在它上面才能读。

**P1.1 与 P1.2 可并行**（改的文件不重叠：P1.1 动 `facts.py:187/989`；P1.2 动 `facts.py:553` + `learn.py`。注意 `learn.py` 是同一文件，需协调，或拆成 `learn_shrink.py` / `learn_semantic.py`）。

**P1.3 建议延后**：没有执行层，探索臂只能规划不能执行，学了也没有样本。等 Amazon Ads API 写权限通了再做。

### ⚠ 上一版的「顺序陷阱」已不存在（因为那个做法被否决了）

上一版写过一段「P1.0 让建议出来、P1.1 让它又没了、P1.2 让它回来」的陷阱。**那是建立在「合并 `lat pulldown` 两个活动」这个被否决的做法之上的，现在不成立。**

新的真实顺序是这样的：

```
现在                词层/活动层都没有达到判定线的动作 → 0 条建议（这是对的）
做完 P1.0           报告明确写出「今日无达到判定线的动作」+ 分层证据 + 组合层已知事实
做完 P1.1           判定线按段自适应（更严），建议仍然可能为 0 —— 这是预期，不是退步
做完 P1.2           否词候选按簇归组展示，建议数量不变
```

**没有哪一步会让建议「回来」，因为本来就不该靠改聚合口径把建议造出来。** 建议什么时候有，取决于数据什么时候够线——这是特性。

**唯一会让建议数量变化的是真实的运营干预**（降价、加预算、否词、Listing 改版），那是人的动作，不是学习层的产出。
