## 一、这份词典管什么

规则引擎（R01–R30）能从数据算出来的，一律不问。**词典只装「数据算不出来、只能由人回答」的原因**。

判断标准只有一条：把这条原因写进程序，能不能自动判定真假？

- 能（如「点击不足 88，样本不够」）→ 自动排除，不进清单
- 不能（如「这个词是故意投的品类大词，允许亏」）→ 进词典，等人打钩

所以词典的条目数量不代表系统复杂度，代表**人的意图无法从数据反推的部分**。

### 判定来源三分类（v1.1 新增，最重要的一条）

每条候选原因必须标注它靠什么判定。**只有「人」才出题**：

| 来源 | 判定手段 | 出现在哪 | 例子 |
|---|---|---|---|
| `数` | 本地库能算 | 报告的「诊断说明」，不出题 | 曝光 <500 → 搜索量小；搜索词集中度 >95% → 匹配不宽 |
| `外` | sorftime 能查 | 报告的「市场旁证」，不出题 | 竞品降价 >5%；ABA 搜索量 12 周下行 >30% |
| `人` | 只能人回答 | **进疑问清单，等打钩** | 「这是故意投的品类词，允许亏」 |

这条规则的作用：v1 有 60+ 条候选，按此分类后**真正出题的不足 20 条**。剩下 40 条改由程序判定，写进报告结论，人不用看。

> 实测依据：Q01 的 lat pulldown，v1 列了 12 个候选。实际数据能直接排除 8 个——曝光 20,329（不是搜索量小）、精确匹配 290 点击里 288 次跑的就是本词（匹配不宽）、归因窗口已过、非新品。剩下真正要问人的只有 4 个。**12 → 4，这就是分类的价值。**

## 二、六条硬规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **触发条件必须可执行** | 每条原因挂在明确的数据条件上；条件不成立就不出题。禁止「你觉得这个词怎么样」 |
| 2 | **候选只放「人」类；一次最多 5 题，每题最多 6 个候选** | 超过 5 题人会全点跳过，回路作废；候选超 6 个打钩成本高于收益 |
| 3 | **未勾 = 未表态，不是排除** | v1 写「未勾 = 排除」，会把人没细看的原因全记成排除、90 天不再问，词典被快速清空。v1.1：只有**显式划掉**才写 `reason_excluded`；未勾只记「本轮未涉及」，下次照常可出 |
| 4 | **跳过整题 = 采用该题默认项** | 默认项一律取最保守分支（不动 / 只观察），登记为「agent 推断假设」，设观察期。到期用数据验：成立升策略，不成立反向修正并提高同类问题再问优先级 |
| 5 | **打钩即沉淀，不留在对话里** | 每个钩子按四类落到 policy / param / observation / experiment 四张表之一，带作用域和到期日；到期自动复核 |
| 6 | **允许「以上都不是」** | 每题末尾固定一个手填入口。穷举一定漏，手填原因进词典 v1.x 候选池，不当场生效 |

**四类只决定落点，不改变交互形式**（交互永远是打钩）：

| 类 | 回答的是 | 落到 | 有效期 |
|---|---|---|---|
| 阻塞 | 这件事到底能不能做 | `policy`（禁改/允许） | 必填到期日 |
| 校准 | 我的默认参数对不对 | `param_override` | 季度复核 |
| 归因 | 这个结果是谁造成的 | `observation_task` | 观察期 7–14 天 |
| 探索 | 这个假设值不值得试 | `experiment` | 实验期 + 对照组 |

### 多选与冲突（v1 未定义，必须补）

打钩是**多选**。真实情况常同时成立（如「Listing 有问题」+「季节性淡季」）。

合并规则，按优先级从高到低取第一条：

1. `freeze`（冻结广告）> `policy`（允许亏）> `observation`（观察）> 出价类动作
2. 同一对象同时出现「冻结」和「观察」→ 冻结生效，观察任务仍然登记（冻结期满后自动接着跑）
3. 同一对象同时出现两个 policy 且参数冲突 → 取更严格的那个，另一条降级为备注，出题时提示「上次有两条冲突，已按严格执行」

## 三、问题类型总览

阶段字段：`冷启` = 冷启动/数据稀薄期，`成长` = 有稳定单量，`成熟` = 结构稳定；`全` = 通用。

| 编号 | 问题类型 | 触发条件 | 出题 | 适用阶段 | 对应规则 |
|---|---|---|---|---|---|
| Q01 | 高花费·低单的关键词 | 窗口花费 ≥ AOV×目标ACOS 且订单 ≤1 且点击 ≥ 判定线 | 每日 | 全 | R01/R30 |
| Q02 | 全店转化率不达标 | CVR < 盈亏平衡 CVR | **周报** | 全 | R30 |
| Q03 | 预算打满要不要加 | 7 天内 ≥3 天预算消耗 >90% 且 ACOS ≤ 目标×1.2 | 每日 | 成长/成熟 | R08 |
| Q04 | 位次加价该升该降 | 某位次点击 ≥ 判定线，且该位次 ACOS 与活动均值偏离 >30% | 每日 | 成长/成熟 | R09 |
| Q05 | 出价已到底价仍无量 | bid ≤ 地板×1.3 且窗口点击 < 判定线 | 每日 | 全 | R01 地板分支 |
| Q06 | 有单但 ACOS 远超目标 | 有单、ACOS > 目标×1.5、命中核心词保护 | 每日 | 全 | R01 保护分支 |
| Q07 | 有点击零单的词（拓词/收割） | 点击 ≥ 判定线 且订单 = 0，或 点击 ≥ 30 且订单 ≥ 1 | 每日 | 全 | R02/R04/R21 |
| Q08 | 搜索词跑偏 | 单条搜索词窗口花费 ≥ $10 且 0 单且与投放词语义无关 | 每日 | 全 | R02 |
| Q09 | 数据异动 | 单日花费/点击/订单偏离前 7 日均值 ±40% | 每日 | 全 | L0 diff |
| Q10 | 竞品动作 | sorftime 检出监控名单内降价 >5%、报活动、BSR 变动 >30% | 每日 | 全 | 外部数据 |
| Q11 | 业务约束（主动申报） | 无数据触发，靠人主动填 | 随时 | 全 | — |
| Q12 | 建议未处理 | 见 §四 Q12（拆两种触发） | 每日 | 全 | 决策层回流 |
| **Q13** | **结构性重复投放** | 同一 `keyword_text` 出现在 ≥2 个活动 | **不出题** | 全 | 新增 |

**阈值参数化（v1.1）**：上表所有「窗口」= `policy.window_by_action_type`，默认 14 天；「判定线」= `min_clicks()` 现算（本店 88）；「花费闸门」= `AOV × 目标ACOS` 现算（本店 $40.94）。**禁止写死数字**——AOV 和目标 ACOS 一变，写死的阈值就失效。

**数据不足时**：窗口实际天数 < 10 天，置信度自动降一档，只出「观察」不出动作。

**出题优先级**：影响金额 × 不确定性。影响金额 = 该对象窗口花费；不确定性 = 1 − 规则置信度（证据「一般」= 0.6，「够」= 0.2）；无规则来源的题（Q11/Q12）取历史默认项命中率，冷启动按 0.5。排序后取前 5。

## 四、原因清单

> 每张表的「来源」列：`人` = 进清单；`数` / `外` = 不进清单，写进诊断说明。v1.1 只列 `人` 类在候选表里，`数`/`外` 类放在「自动判定」区，供报告引用。

### Q01 高花费·低单的关键词

**自动判定区（不出题，直接写结论）**：

| 判定 | 条件 | 结论 |
|---|---|---|
| 样本不足 | 点击 < 判定线 | 只观察，不出建议 |
| 未过花费闸门 | 花费 < AOV×目标ACOS | 不动作 |
| 搜索量小 | 曝光 < 500 | 「不是价格问题，是没人搜」 |
| 匹配不宽 | 单搜索词占该词点击 >95% | 「精确匹配没跑偏，问题不在匹配」 |
| 归因未回 | 窗口末 2 天内 | 顺延重评 |
| 新品冷启 | Listing 上线 < 30 天 | 保护，不出动作 |
| 断货/配送 | 积加库存或 buybox 异常 | 转供应链告警，广告层冻结 |
| 地板已到 | 目标 bid < 地板 | 走 R01 地板分支 |
| **跨活动重复** | 同词出现在 ≥2 活动 | **走 Q13，本题不重复出** |

**候选（只问这些）**：

| 编号 | 候选原因 | 类 | 打钩后落到 | 跳过默认 |
|---|---|---|---|---|
| A1 | 探索性泛词，故意拓流量，允许亏 | 阻塞 | policy `allow_loss` + 月度亏损上限 | 按规则降 bid |
| A2 | 竞品词防守位，占曝光防抢单 | 阻塞 | policy `defend`，ACOS 上限 60% | 按规则降 bid |
| A3 | 品类大词卡位，冲排名/BSR | 阻塞 | policy `position_hold` + 到期日 | 按规则降 bid |
| A4 | 词没问题，是 Listing/价格导致不转化 | 归因 | 转诊断任务，广告层冻结 14 天 | 按规则降 bid |
| A5 | 以上都不是（手填） | — | 进 v1.x 候选池 | 按规则降 bid |

**本题默认项 = 按规则降 bid（不暂停）**。降 bid 可逆、省钱；停用不可逆。默认永远选可逆那一侧。

> v1 的 A7（竞品降价）、A11（季节性）、A8（库存）、A9（归因窗口）、A12（新品）全部移到自动判定区——这些数据能判，不该问人。

### Q02 全店转化率不达标（**周报区块，不进每日清单**）

**为什么降级**：本店 CVR 1.81% 恒低于盈亏平衡 2.40%，这条每天都会触发，等于每天问一遍「为什么转化不行」，人会烦。而且它的候选全在 Listing/价格/评论层，广告层问这些是越界。

**改成**：每周深度诊断时出一个区块，先给自动诊断结论，只在结论冲突时问 1 题。

**自动诊断区（周报直接输出）**：

| 判定 | 数据源 | 结论示例 |
|---|---|---|
| 价格位置 | sorftime `product_detail` 对比同类 | 「你的 $136 vs 竞品中位 $118，贵 15%」 |
| 评论/星级 | sorftime `product_reviews` | 「4.2 星 / 87 评，同类中位 4.4 / 210 评」 |
| 流量结构 | 本地 search term 泛词占比 | 「泛词占花费 62%，比上周 +9pp」 |
| 季节位置 | sorftime `keyword_trend` | 「品类搜索量处近 12 月 38 分位」 |
| 目标合理性 | `breakeven_cvr()` | 「目标 ACOS 30% 需 CVR 2.40%，当前 1.81%，不可达」 |
| 库存/变体 | 积加 | 「3 个变体中 1 个断货」 |

**只问 1 题（结论互相矛盾时才问）**：

| 编号 | 候选 | 类 | 落到 | 默认 |
|---|---|---|---|---|
| B1 | 主图/A+/视频弱，是转化主因 | 归因 | 转 Listing 任务 | 只告警 |
| B2 | 目标 ACOS 就该放宽（认了） | 校准 | param_override 目标 30%→40% | 只告警 |
| B3 | 以上都不是（手填） | — | 候选池 | 只告警 |

| 编号 | 候选原因 | 类 | 打钩后落到 | 跳过默认 |
|---|---|---|---|---|
| C1 | 确实有效，加预算买量 | — | 执行加预算（单次 ≤20%） | 不加，继续观察 |

### Q08 搜索词跑偏

| 编号 | 候选原因 | 类 | 打钩后落到 | 跳过默认 |
|---|---|---|---|---|
| H1 | 完全无关，直接否 | — | 精确否定 | 标记待否（见下） |
| H2 | 竞品品牌词，看要不要打 | 阻塞 | policy `competitor_bid` | 标记待否 |
| H3 | 泛词，应词组否定而非精确 | 校准 | 词组否定 | 标记待否 |
| H4 | 变体/拼写错误，可收 | 探索 | experiment：收为精准词 | 标记待否 |
| H5 | 相关但转化差，先降 bid 不否 | 校准 | 转 R01 | 标记待否 |

**默认项 = 标记待否，攒到 5 条一次批**（v1 是「默认精确否定」，与自己「默认必须保守」冲突）。

理由：否词看着可逆（能删），实际不可逆——被否的词 90 天内不再进来，季节性词、新起量词就永远看不到；删掉之后历史数据链也断了。「语义无关」这个判定本身靠 LLM 猜，健身品类里 `rowing machine` vs `rowing machine for home` 语义相关但意图不同，误否率不低。

**改为**：默认只标记，报告里出「待否清单」，攒 5 条或每周批一次。人明确勾 H1 才执行否定。

### Q09 数据异动

### Q10 竞品动作（sorftime 已接入，2026-11-16）

### Q11 业务约束（主动申报，无触发条件）

> 不由数据触发，由人主动填；不填 = 无约束。填一次，有效期到到期日。入口放报告顶部「本周约束」区块。

| K1 | 清库存（允许 ACOS 上限提高至 X%） | policy `clearance` | 无 |
| K2 | 断货风险（降预算保排名） | policy `stock_risk` | 无 |

### Q12 建议未处理（**v1.1 拆成两种触发，这是最关键的一处修正**）

| 触发 | 语义 | 处理 |
|---|---|---|
| 提交 48h 未打钩 | **没看**（出差/周末/忙） | 催办一次 + 顺延 48h；再超时 → 降优先级，**不记拒绝** |
| 打钩但填了理由 | **不同意** | 触发下方候选，学习原因 |

v1 把两种合成一种、默认「视为不同意，同类 7 天不再提」。后果：人忙一周没看，所有建议被默认拒绝，系统静默 7 天，人以为系统坏了。**「没看」不是负反馈信号，不能当拒绝学习。**

**候选（只在「打了钩但填理由」时出）**：

| 编号 | 候选原因 | 类 | 打钩后落到 | 跳过默认 |
|---|---|---|---|---|
| L1 | 时机不对，过几天再说 | 校准 | 延后 N 天重提 | 同类 7 天不再提 |
| L2 | 数据不对，算错了 | 归因 | 复核计算链，标记该规则待查 | 同上 |
| L3 | 不符合我的策略（策略库没录入） | 阻塞 | 补录 policy | 同上 |
| L4 | 幅度太大，分步来 | 校准 | 改为单次 ≤10% | 同上 |
| L5 | 我自己已经处理了 | — | 记录，抑制重复建议 | 同上 |
| L6 | 不相信这条规则 | 校准 | 该规则置信度下调/停用 | 同上 |

### Q13 结构性重复投放（**v1.1 新增，不出题，直接进诊断**）

**触发**：同一 `keyword_text` 出现在 ≥2 个活动（不论匹配方式）。

**为什么必须加**：实测本店 14 天，**11 个词跨活动重复投放，累计花费 $1,047.23，占关键词层花费 $2,662.50 的 39.3%**。v1 的 12 题完全没有覆盖这一类。

| 词 | 活动数 | 花费 | 点击 | 单 |
|---|---:|---:|---:|---:|
| lat pulldown | 2 | $273.24 | 290 | 2 |
| rowing machine | 2 | $212.87 | 154 | 3 |
| lat pulldown machines | 2 | $147.16 | 219 | 1 |
| rowing machines for home | 2 | $127.86 | 91 | 2 |
| cable machine | 2 | $79.18 | 111 | 0 |
| rowing machines for home foldable | **4** | $69.66 | 65 | 0 |
| foldable rowing machine | 3 | $53.72 | 44 | 0 |

**更严重的是它让建议金额失真**：R01 建议「停用 lat pulldown 省 $175.22」，但该词在两个活动共花 $273.24（活动 A $186.18 / 活动 B $87.06）。停掉一个，另一个会接走流量——**「省 $175.22」是账面数字，不是真实节省**。真实节省要按词族算，且要考虑预算转移。

**输出形式（不出题，写进报告第二节之前）**：

```
⚠️ 结构问题：11 个词在多个活动重复投放，占关键词花费 39.3%
   - rowing machines for home foldable 在 4 个活动，$69.66 / 65 点击 / 0 单
   - lat pulldown 在 2 个活动，$273.24 / 290 点击 / 2 单（ACOS 100%）
   建议：先做活动归并，再谈降 bid——否则降一个涨一个。
```

**处置**：这属于结构手术，不进每日 ≤5 题。写进周报的「结构问题」区块，由人决定是否归并活动。归并前，R01 对该词族的建议要加一行「本词在 N 个活动投放，实际节省取决于归并方案」。

## 五、沉淀与去重

```
打钩 → 写对应表（policy / param_override / observation_task / experiment）
     → 写 reason_hit（object_id, reason_code, scope, evidence_text, created_at）
     → 该 scope 内同 reason_code 在有效期内不再出现在清单
显式划掉 → 写 reason_excluded（object_id, reason_code, 90 天）
未勾     → 不写任何表（本轮未涉及）
跳过     → 采用该题 default_action，写 agent_assumption（假设 + 观察期 + 到期复核日）
```

**scope 三档**：`object`（这个词/这个活动）、`family`（这个词族/这个活动类型）、`account`（全店）。打钩时默认 `object`，人在依据里写「所有竞品词都这样」才升到 `family`。

**词族定义**：`family` 需要程序判——按关键词的 stem 归并（去掉复数/词序差异）。实测 `lat pulldown` / `lat pulldown machines` / `lat pulldown machine` 属同一词族，合并后 $560.39 / 615 点击 / 4 单 / ACOS 79.6%。

**到期复核**：观察任务到期由引擎自动跑一次判定——假设成立则升级为 policy 并标 `verified`，不成立则写 `refuted` 并提高同类问题再问权重（下次优先出）。

### 表结构（v1 只有表名，schema_v2.sql 里一张都没有，此处补 DDL）

```sql
CREATE TABLE IF NOT EXISTS policy (
    policy_id      INTEGER PRIMARY KEY AUTOINCREMENT,
    scope          TEXT NOT NULL,          -- object | family | account
    object_id      TEXT NOT NULL,
    policy_type    TEXT NOT NULL,          -- allow_loss/defend/position_hold/cold_start/
                                           -- clearance/strategic/freeze/tos_protect/
                                           -- tos_defend/competitor_bid/price_match/
                                           -- no_match/test_period/stock_risk/account_block
    params_json    TEXT,                   -- 如 {"acos_cap":0.6,"monthly_loss_cap":200}
    source         TEXT NOT NULL,          -- 主人原话 | agent推断
    evidence_text  TEXT,                   -- 打钩时填的依据
    status         TEXT NOT NULL DEFAULT 'active',  -- active|verified|refuted|expired
    created_at     TEXT NOT NULL,
    expires_at     TEXT,                   -- 阻塞类必填
    reviewed_at    TEXT
);

CREATE TABLE IF NOT EXISTS param_override (
    override_id    INTEGER PRIMARY KEY AUTOINCREMENT,
    scope          TEXT NOT NULL,
    object_id      TEXT NOT NULL,
    param_key      TEXT NOT NULL,          -- target_acos/account_daily_budget/window_days...
    param_value    TEXT NOT NULL,
    source         TEXT NOT NULL,
    evidence_text  TEXT,
    created_at     TEXT NOT NULL,
    expires_at     TEXT                    -- 季度复核
);

CREATE TABLE IF NOT EXISTS observation_task (
    task_id        INTEGER PRIMARY KEY AUTOINCREMENT,
    object_id      TEXT NOT NULL,
    reason_code    TEXT NOT NULL,
    hypothesis     TEXT NOT NULL,          -- 「假设：这是季节性淡季」
    metric         TEXT NOT NULL,          -- 看什么指标
    judge_rule     TEXT NOT NULL,          -- 到期怎么判成立/不成立
    created_at     TEXT NOT NULL,
    due_at         TEXT NOT NULL,
    result         TEXT,                   -- verified | refuted | inconclusive
    resolved_at    TEXT
);

CREATE TABLE IF NOT EXISTS experiment (
    experiment_id  INTEGER PRIMARY KEY AUTOINCREMENT,
    object_id      TEXT NOT NULL,
    reason_code    TEXT NOT NULL,
    hypothesis     TEXT NOT NULL,
    change_json    TEXT NOT NULL,          -- 改什么
    control_json   TEXT NOT NULL,          -- 对照组是谁
    metric         TEXT NOT NULL,
    created_at     TEXT NOT NULL,
    ends_at        TEXT NOT NULL,
    result         TEXT,
    evidence_level TEXT                    -- 强|中|弱（弱不进 policy）
);

CREATE TABLE IF NOT EXISTS reason_hit (
    hit_id         INTEGER PRIMARY KEY AUTOINCREMENT,
    object_id      TEXT NOT NULL,
    reason_code    TEXT NOT NULL,          -- Q01-A1 这种
    scope          TEXT NOT NULL,
    evidence_text  TEXT,
    created_at     TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS reason_excluded (
    excluded_id    INTEGER PRIMARY KEY AUTOINCREMENT,
    object_id      TEXT NOT NULL,
    reason_code    TEXT NOT NULL,
    created_at     TEXT NOT NULL,
    expires_at     TEXT NOT NULL           -- created_at + 90 天
);

CREATE TABLE IF NOT EXISTS agent_assumption (
    assumption_id  INTEGER PRIMARY KEY AUTOINCREMENT,
    object_id      TEXT NOT NULL,
    question_code  TEXT NOT NULL,          -- Q01
    default_action TEXT NOT NULL,          -- 跳过时采用的默认项
    created_at     TEXT NOT NULL,
    review_at      TEXT NOT NULL,
    result         TEXT                    -- verified | refuted
);

CREATE TABLE IF NOT EXISTS competitor_watchlist (
    asin           TEXT PRIMARY KEY,
    label          TEXT,
    watch_dims     TEXT NOT NULL,          -- price,bsr,rating,promo
    thresholds_json TEXT,                  -- {"price_drop":0.05,"bsr_move":0.30}
    active         INTEGER NOT NULL DEFAULT 1,
    created_at     TEXT NOT NULL
);
```

## 七、v1.1 的边界（明说没做的）

1. **原因条目是穷举，不是收敛**。v1.1 有 60+ 条，按判定来源分类后真正出题的不足 20 条。跑 4 周后用 `reason_hit` 统计，命中 <2 次的降级为「不主动出、可手填」。
2. **Q10 的竞品名单还是空的**，要先人工填 ≤10 个 ASIN 才能跑；sorftime 是轮询式，不是推送式，credit 预算需实测校准。
3. **Q11 靠人主动填**，第一版不做提醒机制（提醒多了变噪音）。
4. **没有跨账户迁移**。所有 reason_code 只在本店语境下校准。
5. **默认项是保守假设，不是最优解**。作用是「不打扰」而不是「做对」；连续 3 次默认被证明正确，才考虑升级为策略。
6. **Q13 只检测同词跨活动，不检测同词跨匹配方式的意图差异**（如广泛跑出的词又在精确里投——这可能是故意的收割结构）。后者需要人判，暂不自动告警。
7. **词族归并只做 stem 级**，不做语义级。`lat pulldown` 与 `lat pulldown machine` 能归并，`rowing machine` 与 `row machine` 归并不了，会漏。
