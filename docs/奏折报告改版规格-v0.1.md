## 二、压缩规则（第 5 段）

1. 未达判定线的词一律进「只看不动」，不占建议名额。
2. 够线的建议按 `spend_impact` 绝对值降序。
3. 再套规则配额：R01 最多 3 条，R30 最多 1 条；其余规则配额 P1 实现时按当周分布再写进配置，缺省各最多 2 条。
4. 配额或 8 条之外的够线建议，进折叠区，不删除。
5. 当日建议不足 3 条算正常。「今天没有值得动的」是正式输出，不是失败。
6. 禁止为凑满 8 条把不够线的词抬进建议区。

## 三、打钩落点

未勾 = 未表态，不是排除。显式划掉才写 `reason_excluded`。跳过整题 = 采用该题保守默认，登记 `agent_assumption` 并设观察期。

| 类 | 写到 |
|---|---|
| 阻塞 | `policy` |
| 校准 | `param_override` |
| 归因 | `observation_task` |
| 探索 | `experiment` |
| 建议本身已做 / 未做 / 理由 | `decision_log` 的 `checked_at` / `checked_by` / `reject_reason` |

## 四、归因对照

第一版对照是「同一对象改前窗口 vs 改后窗口」。同词族其他词只作旁证，不写成 A/B。弱证据只留在观察任务；中等以上才允许进入 `policy`。
