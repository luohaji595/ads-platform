## 三、卡兹克四层怎么落到本船

| 卡兹克 | 本船落地 | 明确不抄 |
|---|---|---|
| 事件进中台，按规则派单、去重、留痕 | 接在已有 launchd 之后：ingest / engine 收尾写事件，中台只消费 | 不为每类事件再写一套脚本，也不再加一套定时器 |
| 本地 Agent 执行 | 现有岗位机器人执行，船长做单一出口，每天只出一张奏折 | 不新建岗位 |
| CI：Agent 干到开 PR，自己不能上线 | 守门员质检 + 待批清单 + 反馈层。Agent 干到待批为止 | 不搬代码仓库、虚拟机和自动发布 |
| 飞书卡片批奏折 | 本聊天勾选包 | 不把飞书改成主审批入口 |
| 「定的事」「定了不做的事」 | 先写入库内策略表，再投影到 gbrain | 不以聊天记忆代替台账，也不让 Markdown 成为唯一写入点 |

第一版必须推到奏折的事不变：花钱；改价、改预算、否词、启停、建活动、建受众包；对外发消息；补发、退款；新建或修改机器人与例行；密钥和权限；清货与备货下单；改产品方向。第一版里这些以外的事也先进入奏折或日报，不自动执行。预授权要到 P3 且单独点头才讨论。

## 五、目标链路与报告改版

```
已有调度：06:10 ingest  →  07:00 engine
                        │ 收尾各写一条 event（含写入方）
                        ▼
              ┌───────────────────┐
              │  本船事件中台      │  只消费、去重、派单、留痕
              │  rules.yaml       │  单一出口：船长
              └───────────────────┘
                        │
              广告投手起草 + 运营数据分析出数
                        │ 对外文案 / Listing 先过守门员
                        ▼
              每日奏折（送到本聊天）
                        │ 家洛打钩 / 划掉 / 跳过 / 补依据
                        ▼
              写入库内表，再投影到 gbrain
                        │ 按动作类型开归因窗
                        ▼
              反馈层复盘 → 下一轮
```

奏折六段以 v1.3 为准，在现有 `render_report` 上改，不另起一套互不相认的报告：

| 奏折六段（目标） | 现有六节怎么处理 |
|---|---|
| 一、账户状况 | 保留「一、账户现在什么状况」 |
| 二、结构问题（Q13，不出题） | 新增 |
| 三、自动诊断 | 并入并改写现有「四、为什么大部分词没动」；「五、样本不够」和「六、配置变更」归进本段的折叠区，不删 |
| 四、需要回答的问题（最多 5 题） | 新增打钩表 |
| 五、今天该做什么（软目标 8 条） | 现有第二节，移到这里，并加上压缩规则 |
| 六、每条建议是怎么算出来的 | 保留现有第三节 |

压缩规则（待拍板第 4 条通过后执行）：先把未达判定线的词留在「只看不动」，不占建议名额；够线的建议按 `spend_impact` 绝对值降序，再套规则配额；超出 8 条的进折叠区。不为凑满 8 条把不够线的词抬进建议。

归因窗的对照，第一版不用同账户同词同时两个出价（做不到）。默认对照是「同一对象改前窗口 vs 改后窗口」；同词族其他词只作旁证，不写成 A/B。这只能得到弱或中等证据。中等以上才允许进入 `policy`；弱证据只留在观察任务里，避免策略表长期空转或被弱证据填满。
