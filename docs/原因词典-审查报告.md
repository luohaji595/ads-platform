## 二、P0 问题详证

### P0-1：可自动判定的原因混进了清单

v1 自己的硬规则第 1 条写「触发条件必须可执行，禁止『你觉得这个词怎么样』」。但 Q01 给 lat pulldown 列了 12 个候选，用实测数据一跑：

| v1 候选 | 实测数据 | 能否自动判 |
|---|---|---|
| 搜索量小 | 曝光 **20,329** | ✅ 能 → 排除 |
| 匹配太宽/跑偏 | 290 点击里 **288 次跑的就是本词**（99.3% 精准） | ✅ 能 → 排除 |
| 归因窗口没过 | 窗口 10-31~11-13，已排除末 2 天 | ✅ 能 → 排除 |
| 新品冷启动 | Listing 已上线 >30 天 | ✅ 能 → 排除 |
| 断货/配送异常 | 积加库存可查 | ✅ 能 → 排除 |
| 竞品降价 | sorftime `product_trend` 可查 | ✅ 能 → 排除 |
| 季节性淡季 | sorftime `keyword_trend` 可查 | ✅ 能 → 排除 |
| 出价已到地板 | 目标 bid $0.40+ 高于地板 $0.40 | ✅ 能 → 排除 |
| 探索性泛词允许亏 | — | ❌ 只能人答 |
| 竞品词防守 | — | ❌ 只能人答 |
| 品类大词卡位 | — | ❌ 只能人答 |
| Listing/价格不转化 | — | ❌ 只能人答（但可先给诊断结论） |

**12 个候选 → 真正要问人的 4 个。** v1 让人看 12 条，其中 8 条是噪音，会直接导致「全部跳过」。

**修订**：每条候选强制标注判定来源，三分类：
- `数` = 本地库能算 → 写进「自动诊断」，不出题
- `外` = sorftime 能查 → 写进「市场旁证」，不出题
- `人` = 只能人答 → **才进清单**

这条规则一旦执行，词典条目从 60+ 降到真正出题不足 20 条。**词典型设计的第一原则不是"穷举全"，是"只问数据问不出的"**。

### P0-2：完全没覆盖跨活动重复投放（最严重的遗漏）

v1 的 12 题全部是「单个对象内部」的问题（这个词好不好、这个活动要不要加预算、这个位次要不要加价）。**没有一题看对象之间。**

实测 14 天，同一关键词出现在多个活动：

| 关键词 | 活动数 | 花费 | 点击 | 单 | 备注 |
|---|---:|---:|---:|---:|---|
| lat pulldown | 2 | $273.24 | 290 | 2 | 见下 |
| rowing machine | 2 | $212.87 | 154 | 3 | |
| lat pulldown machines | 2 | $147.16 | 219 | 1 | |
| rowing machines for home | 2 | $127.86 | 91 | 2 | |
| cable machine | 2 | $79.18 | 111 | 0 | |
| **rowing machines for home foldable** | **4** | $69.66 | 65 | 0 | 4 个活动抢一个词 |
| foldable rowing machine | 3 | $53.72 | 44 | 0 | |
| **合计（11 个词）** | | **$1,047.23** | | | **占关键词层花费 $2,662.50 的 39.3%** |

lat pulldown 的两个活动：
- `L3-基础bid0.8 top-lat pulldown-fix`：$186.18 / 234 点击 / 1 单
- `L3-基础bid0.4 溢价1.4 top-lat pulldown-fix`：$87.06 / 56 点击 / 1 单，CPC $1.555

> **⚠ 2026-11-17 勘误**：本行原写「出价 0.4×1.4=0.56，实际付出近 3 倍 → 两个活动在互相抬价」。**该判断错误**：活动名里的「溢价1.4」不是真实配置，`fact_placement_daily` 实测该活动 TOS 的 `bid_adjustment=350%`，上限是 0.40×4.50=**$1.80**，实际 CPC $1.6174 只占 **89.9%**，未超上限。详见 `docs/原因词典-v1.3.md` §六 Q13 的 v1.3.1 勘误。

**这为什么是 P0**：它让 R01 的建议金额失真。R01 说「停用 lat pulldown 省 $175.22」，但该词实际花 $273.24。停掉一个活动，另一个会接走流量——**省下的钱不是 $175.22，可能是 $0，只是换了个活动花**。人在审批时看到「省 $175.22」会以为真的省了。

**修订**：新增 Q13，不出题、进报告「结构问题」区块，并给 R01 加一条备注：「本词在 N 个活动投放，实际节省取决于归并方案」。

### P0-3：Q12 把「没看」当成「不同意」

v1 原文：提交 48h 未打钩 → 视为不同意 → 同类 7 天不再提。

**问题**：人会出差、过周末、忙。一次没看，系统就把它记成「主人拒绝了这条建议」，并且 7 天内不再提同类。人回来发现系统安静了，以为坏了。

「没看」和「不同意」是两种完全不同的信号：
- 没看 = 没有信息，不能学习
- 打钩但填理由 = 明确反对，必须学习

**修订**：
| 触发 | 语义 | 处理 |
|---|---|---|
| 48h 未打钩 | 没看 | 催办一次 + 顺延 48h；再超时降优先级，**不记拒绝** |
| 打钩 + 填理由 | 不同意 | 出 L1–L6 候选学习原因 |

## 三、P1 问题

### P1-4：「未勾 = 排除」会把人快速清空词典

v1 原文：没勾的视为排除，同样的原因不再重问。

人会偷懒：一屏 12 条候选，勾 2 条，剩下 10 条没勾——不是「这 10 条都排除了」，是「我没细看」。

**修订**：未勾 = 未表态，不写任何表。只有**显式划掉**才写 `reason_excluded`（90 天）。多一步动作，但保住了词典。

### P1-5：Q08 默认「精确否定」与自己冲突

v1 硬规则写「默认必须保守」，但 Q08 默认精确否定。否词看着可逆（能删），实际不可逆——被否的词 90 天内不再进来，季节性词、新起量词永远看不到；删掉后历史链也断了。且「语义无关」这个判定靠 LLM 猜，`rowing machine` vs `rowing machine for home` 语义相关但意图不同。

**修订**：默认「标记待否，攒 5 条或每周批一次」。人明确勾 H1 才执行。

### P1-6：Q02 是恒真题且越界

本店 CVR 1.81% 恒低于盈亏平衡 2.40%，Q02 **每天都会触发**。每天问一遍「为什么转化不行」，人会烦；且候选全在 Listing/价格/评论层，广告层问这些是越界。

**修订**：降级为周报区块。先给自动诊断结论（价格位置/评论/流量结构/季节位置/目标合理性/库存），只在结论互相矛盾时问 1 题。

## 二、v1.1 的 3 个 P0，v1.2 全部原样保留

### P0-1（最致命）排序公式自相矛盾，照字面实现会每天问错题

v1.2 第 88 行原文：

> 出题按「影响金额 × 不确定性」排序，取前 5。影响金额 = 该对象窗口花费；不确定性 = 1 − 规则置信度（证据「一般」= 0.6，「够」= 0.2）

括号里把「证据够」标成 0.2。两种读法都错：

| 读法 | 推论 | 后果 |
|---|---|---|
| 0.2 是**置信度** | 证据越足 → 置信度越低 → 不确定性 = 1−0.2 = 0.8 越高 | 我已经很确定原因的题，反而排到最前面问 |
| 0.2 是**不确定性** | 与「1 − 置信度」公式对不上（0.6 那档应是 1−0.4） | 实现者无所适从，两人写出两套排序 |

正确写法只有一种：
> 不确定性 = 1 − 置信度。证据「够」→ 置信度 0.8 → 不确定性 0.2；证据「一般」→ 置信度 0.6 → 不确定性 0.4。

### P0-2（更深，v1.1 和 v1.2 都没发现）这个公式对「人」类题根本不成立

硬规则 1 + 硬规则 2 规定：**只有 `人` 类候选能进清单**。而 `人` 类的定义就是「数据判不了」——它的规则置信度**恒等于 0**。

那么 `不确定性 = 1 − 0 = 1`，对每一道题都是同一个常数。

**「影响金额 × 不确定性」直接退化成「按花费排序」。**

v1.2 自己其实碰到了这个洞却没意识到——它写「无规则来源的题（Q11/Q12）取历史默认项命中率，冷启动按 0.5」，说明它知道有些题没规则来源；但它没往下推一步：**所有进清单的题都没规则来源**，否则不该进清单。

修法（三选一，推荐第一种）：
1. 不确定性改为「历史跳过率」：同一 reason_code 被跳过 3 次 → 不确定性 0.9。跳过即承认拿不准，这是唯一有真实信息的信号。
2. 不确定性改为「最坏损失占比」：不处理的话，窗口剩余天数 × 当前日均花费，占账户日花费的比例。
3. 干脆承认第一版没有可靠的不确定性，排序只用「影响金额」，并在报告里标注「本期按花费排序」。**这比编一个假公式诚实。**

### P0-3 首日 7 题 vs 硬规则「一次≤5」，v1.2 把它写成了「不补编」

v1.2 第 385 行原文：

> 原文将首日清单计为 Q01（词族合并后 1 题）+ Q03（1 题）+ Q04（2 题）= 4 题……Q06、Q07、Q08 也触及触发条件，它们如何从每日 ≤5 题里落下，原文未写明，**此处不补编**。

它抓到了矛盾（这是它的贡献），但处理方式是**把审查报告该说的话写进了规则文件**。

规则文件不能留「未写明」。系统第一次跑就会吐 7 题，主人打开看到 7 题，直接违反硬规则 2，回路第一次就失效。

必须补一条裁决规则，例如：
> 超限时按「影响金额 × 不确定性」取前 5，其余进「今日只观察」区块（不出题、不占额度）；被挤下去的题在下一轮优先补位，连续 3 轮被挤则强制进清单。

## 三、v1.2 新引入的 3 个问题

### N-1 Q07 收割阈值 30 是硬编码魔法数字

v1.2 写：「收割：点击 ≥ 30 且订单 ≥ 1」。

- 判定线是 `min_clicks()` 现算的 **88**，这里突然出现一个写死的 **30**，两者差 2.9 倍。
- 30 从哪来？没写。违反 v1.2 自己的硬规则 1（触发条件必须可执行）和 v1.1 的「阈值不许写死」。
- 逻辑上也说不通：30 点击 × CVR 1.81% ≈ 期望 0.54 单，还不到 1 单，凭什么认定这个词「稳定有转化」？

修法：收割阈值同样走公式，例如 `clicks ≥ ceil(1 / CVR_baseline)` 或直接复用 `min_clicks()` 的 1/3 档，并在文档写明档位理由。

### N-2 Q02 的「触发若会天天成立」不可执行

v1.2 写：「触发若会天天成立，或候选落在 Listing/价格/评论层，则改为每周深度诊断」。

「会天天成立」是人话，机器判不了——它要求系统预判未来。v1.1 原本写的是可执行的：「CVR < 盈亏平衡 CVR 恒成立 → 周报」。**v1.2 把一个可执行条件改成了不可执行条件，这是退步。**

修法：回到可判定式——「该条件在最近 14 天窗口内 14/14 天成立，或该条件不含可动对象（全店级），则降为周报」。

### N-3 删掉「为什么」，只留「是什么」

v1.2 自述「正文去掉……重复说明」。但被删掉的不只是重复说明，还有**理由**。最典型是 Q08：

| 版本 | 内容 |
|---|---|
| v1.1 | 保留完整理由：否词看着可逆实际不可逆、90 天不回流、LLM 语义判定误否率不低、`rowing machine` vs `rowing machine for home` 的具体反例 |
| v1.2 | 只剩一句「否词 90 天内不再回流，默认必须保守」 |

对规则文件来说这是危险损失：将来有人要改 Q08，看不到「LLM 语义判定误否率高」这条依据，就会以为可以用 LLM 预筛，改错方向。**「为什么」是边界情况下的唯一判断依据。**

建议：正文保留一句「为什么」（不超过 30 字），详细理由进实现说明的附录。

## 五、Q09 的「需 7 天数据」是误判（v1.1 起，v1.2 照抄）

v1.2 第 364 行：「Q09 | 待补 | 需连续 7 天数据才能判 ±40%（现 13 天）」。

**13 天数据完全够算 7 日均值。** 这条把能判的说成不能判，白丢一个自动诊断。且 `fact_campaign_daily` 有 `campaign_state` / `serving_status` 字段，Q09 的主体（广告被拒/暂停）本来就能直接判，不需要等。

## 六、结论与建议

| 判断 | 说明 |

| 能不能用 | **不能。** 排序公式会让系统每天问「证据最足」的题，而证据足的题本不该进清单 |
| 该做什么 | 出 v1.3，只做三件事：修 P0-1 排序公式、补 P0-3 超限裁决、修 N-1 的 30 |
