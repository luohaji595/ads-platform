## 三点五、规则引擎横向深挖结论（2026-11-14 增补）

用户判断"规则引擎才是最值钱的"，已完成跨平台横向取证，产出 **06-规则引擎深挖-跨平台规则库.md**。五条可直接落代码的结论：

1. **最优 bid 是闭式公式，不是"ACOS 超标就降 X%"**：有销售额 `bid=(销售额/点击)×目标ACOS`；有售价 `bid=售价×目标ACOS×CVR`；**无销售额 `bid=售价×目标ACOS÷点击`（点击越多自动衰减，天然替代固定 step，IvyeaOps 缺此条）**。
2. **花费闸门**：`花费 < 售价×目标ACOS 且 当前bid < 最优bid → 不动手`，消掉大量低样本噪声候选。
3. **bid 必须归一化**：`目标bid × (100 ÷ (100 + placement加价%))`，否则算出的价被 Amazon 位次加价与 Dynamic Up&Down 放大，实际 ACOS 系统性偏离。
4. **目标×盈亏锚点双输入**（Teikametrics）：ACOS Limit=广告前毛利率，Goal 决定允许区间（Launch 100–125%、Grow 95–100%、ROAS/Profit 1–100%、Liquidate 100–150%）。
5. **新增两类机制**：Ad Badger「抑制-试探状态机」（降到底价仍不赚→抑制，按活动健康度决定是否反向试探）与 Perpetua「限时人工覆盖+到期自动还原」（补 D4 回滚缺口）。

建议模块 3 修订：规则数 5→11；bidding 加无单衰减公式与花费闸门；冷却期改双参数窗口（daysToAnalyze + daysToIgnore）；审批补"Review 模式批量批准"；回滚补"到期自动还原"路径。

## 三点六、规则库 v2：技能包 + 中文工具（2026-11-14 增补）

用户指出"挖掘渗透不够、很多规则 skill 没拿到"，补完本地技能包与中文工具层，产出 **07-规则库v2-技能包与中文工具.md**。四条结论：

1. **规则总数 16→30 类**，新增 14 类里 4 类是海外平台完全没有的：**关键词卡位（按排名位置反推出价）**、自我竞争检测、实时当日数据策略、执行异常监控。
2. **最值钱的不是规则数量而是防错设计**：① `ACOS=0 不等于好`（销售额/订单为 0 时 ACOS/CPA 也返回 0，用它们做判据必须附加"订单≥1 或 销售额≥1"）② 排除近 1–7 天归因滞后窗口（官方建议排除近 2 天）③ 改完 5–7 天内不许再动同一对象。
3. **规则作用域是三层**：广告对象 → **策略（可复用 + 版本号）** → **执行计划（提前 1 小时生成 + 执行时留存当时指标）**。模块 3 目前缺"策略"层。
4. **PPC 数据链分工必须钉死**：Amazon Ads API 给 E1（花费/点击/订单/ACOS）；Sorftime 与西柚只给 E4（搜索量/CPC 参考/排名/竞品词），**Sorftime 无花费点击订单，不可替代 E1**。阻塞项：Sorftime 套餐配额耗尽、西柚 token 不在当前 shell。

另外补齐 Amazon 物理约束校准：动态竞价 up&down **所有位次最多 ±100%**（2026 现行口径），故 `effective_bid = base_bid × (1+placement%) × dynamic_factor`，`dynamic_factor ∈ [0,2]`——06 的归一化公式漏了这一层。位次加价上限 900%。



## 三点七、积加自身广告自动化能力（2026-11-14 增补）

用户问"积加的广告 agent 是干什么的、怎么设置自动调节"，做了一次**只读**调查（官方帮助中心 + 1 次只读 API），产出 **08-积加广告自动化能力拆解.md**。五条结论：

1. **"广告 agent"是两个东西**：官方术语「广告自动化」= **自动策略（按表现）+ 分时策略（按时间）**；另加第三套 **广告抢位（按排名）**，抢位不在该术语内但**优先级最高，运行时其他自动规则全部失效**。
2. **积加AI（aiagent.app.gerpgo.com）不是执行器**：数字员工 + 长期任务 + 技能，广告日常监控被官方标为「场景3 内测中」，只出报告/建议，**不改 bid**。
3. **三套调度器频率各不相同**：自动策略"每 N 天 + per-object 冷却"、分时策略"每 2 小时判断/整点生效"、抢位"每小时跟踪排名"。自建平台若只做一套调度，无法复现这三层。
4. **OpenAPI 零写接口**：25 个 `/operation/ads/*` 全为 `query`/`page`；策略侧只有 `strategyTemplate/page`（只读分时策略）。**自动策略与抢位在 API 里完全不存在** → 积加的自动化配置既读不全也写不进，规则引擎必须自研。
5. **本账号实测**：`strategyTemplate/page` 返回 1 条模板，`useNum=0`（未挂任何广告活动）、`status=1`、基础预算 $40、0-6 点调至 $15 / 6-24 点调至 $40 → **积加侧实际没有在跑任何自动调节**。

**新增一条取数备选**：官方营销页明说积加AI 有「MCP套餐」（仅 MCP 数据接口，"适合自研智能体的技术团队"），可把 ERP 数据封装成 MCP 给外部 AI 读——这是除 OpenAPI 之外的第二条通道，模块1 可评估。
可直接抄的三个设计：①**数据范围三选一（周期/累计/当日）+ 前 M 天**（把归因滞后窗口做成一等公民）②**冷却按 per-object 且只在"真优化"时起算** ③**基准三选一 + 明确的手动干预语义**（"人工改了价格系统怎么办"的唯一正确答案形态，05 完全没写）。
新增三条实现约束：①**SP 自动活动不能改关键词 bid，只能改投放组**（规则引擎必须先读 targetingType）②分时策略每 2 小时才判断，预算阈值不能设太紧（官方建议剩余 20%/30% 时再提高）③抢位与其他规则**硬互斥**，否则互相打架。


## 三点八、积加AI 的 Agent / Skill / Tools 四层（2026-11-14 增补）

用户指定要弄清「积加AI 的 agent、skill 和能力」，做了一次**匿名静态分析**（只读公开前端 JS bundle + 公开帮助文档，未登录、未调积加 MCP、未做鉴权探测），产出 **09-积加AI-Agent与Skill能力拆解.md**。六条结论：

1. **四层架构**：`长期任务（定时器+固定提示词≤2000字）→ 数字员工 Agent（绑定 Skill[]）→ Skill（SKILL.md）→ MCP Tools（19 个 server）`。**只有最底层碰真实数据，上面三层全是提示词与调度。**
2. **Skill 就是 Anthropic SKILL.md 规范**（代码级证据：前端 `ch/index.8b651a97.js` 把 `{name:skillCode, description, tools}` 序列化成 YAML frontmatter 拼在正文前）。`skillCode` 即 frontmatter 的 `name`。
3. **官方只有 7 个技能，全是"分析→建议"，零执行型**：Amazon评论分析×2、意图分析、Amazon商品诊断、Amazon经营月报、Amazon销量预测、效果分析优化。**没有一个是改 bid / 加否词 / 调预算的。**
4. **官方只有 3 个数字员工**（通用商品优化 / 优化效果分析 / 商品优化），技能完全相同、只差提示词与筛选条件 → **Agent 的差异 = 提示词差异，不是代码差异**（不可回归测试，我们不抄）。
5. **长期任务官方自述处于"阶段1 半智能"**：AI 出建议 → 真人判断 → **真人执行**；阶段2 半介入、阶段3 全智能都是路线图。后台执行链里**没有"执行动作"这一步**，产物只有报告。
6. **能力底座 19 个 MCP server**：积加自有 15 个 `gerp-*` + 三方 4 个（卖家精灵/SIF/Sorftime/西柚洞察）。广告相关只有 `gerp-ads`(21 tools) 与 `gerp-ads-v2`(18 tools)，**全是 page/trend 查询，零写操作**；单 tool 成功计 1 点，点数池跨 provider 共享。

**可抄三个设计**：①**Skill = SKILL.md + tools 白名单 + 可用用户**（规则从代码变成可版本化可分配的文本，正解 07 规则26「策略版本化」）②**`specifyResponseFields` 字段裁剪**（AI 只取要的列，比"少查数据"更直接）③**`_page` 明细 + `_trend` 趋势双接口**（LLM 先看趋势再决定要不要拉明细，省 token 最有效的一招）。
**不能抄四条**：①Agent 只靠提示词区分（无法回归测试）②巡查维度只有 ASIN（广告最小决策单元是 keyword / search term）③只出建议不执行 ④结果推送只有 ERP 站内消息。
**新增三条实现约束**：①**规则必须声明它能用的数据源**（等价 tools 白名单），执行时校验"规则要的字段 ⊆ 规则被允许看的字段" ②**每条规则必须绑一个"效果校验"钩子**（积加列表页有 `是否需要效果校验` + `效果检验Agent` 两列，方向正确但未启用）③**LLM 复核的 prompt 必须当配置版本化**，不能拼在代码里。
